# novel-atlas 設計書

小説の執筆・分析環境を `shogi-atlas` と同じ 3 層(公開 PWA / 非公開データリポジトリ / Claude のルーティン)で作り直すための設計。
依頼者の承認を得るまで、実装・リポジトリ作成・`novel-hoshiyomi` の変更をしない。

**このディレクトリは public リポジトリに入る。**
例には公開済みの本文から読み取れる事実か架空のものだけを使う。
未公開の設定(根幹・伏線の答え・結末)は書かない。

## 要点

- 依頼者が初回の検出係にならないよう、機械で判定できる検査はすべて GitHub Actions の必須チェックにする。
  チェックが緑になり内部レビューが済むまで、PR は依頼者の読む段階(`stage:reading`)に進まない。
- 設定資料は YAML にする。
  照合は「本文から抽出した事実(claims)」と canon の `確定` 項目の突き合わせで行う。
  抽出だけを LLM が行い、判定は決定的なスクリプトが行う。`仮` の項目との食い違いは通知に留める。
- 公開/封印の区分は廃止する。
  隔離レビュアーには、本文だけを集めた一時ディレクトリ(隔離バンドル)を渡す。
  ファイルの置き場所ではなく、渡す物を絞って隔離する。
- 依頼者はビューアで本文を読み、段落を選んでコメントする。
  1 回の読了ぶんを 1 件のレビューにまとめて送り、ルーティンが一括で反映して各コメントに返信する。
- PR のコメントは `feedback/` に構造化して残し、口調・語彙・再発防止規則・嗜好へ蒸留する。
- 1 段目は「`novel-atlas-data` へ移行し、第 7 話を新しいループで書ける」ところで区切る。
  claims による canon 照合と他作品の解析は 2 段目以降に回す。

## 依頼者に先に決めてほしいこと(詳細は 08)

1. Codex の GitHub 自動レビューを隔離レビュアーとして扱うか。
   話設計書と初稿が同じ PR にあるかぎり、Codex は設計情報を見る。
2. 隔離レビュアーを物理的に隔離する実行方法。
3. データリポジトリのパスを ASCII にするか日本語にするか。
4. マージ(確定)を GitHub の画面で行うか、ビューアのボタンで行うか。
