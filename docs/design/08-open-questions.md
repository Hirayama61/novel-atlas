## 依頼者に決めてほしいこと

### Q1. Codex の GitHub 自動レビューの位置

話設計書と初稿が同じ PR にあるので、Codex の自動レビューは設計情報と canon を見たうえで本文を読む。

- **A(推奨)**: 自動レビューは「設計を知る第三者の整合レビュー」として使う。隔離された Codex の読みと採点の 3 件目は `codex exec` で隔離バンドルに対して行う。
- B: 設計と本文を別 PR に分け、本文 PR には設計を入れない。Codex の自動レビューが隔離になるが、決定 7(同じ PR に push)を変えることになる。
- C: 隔離をあきらめ、自動レビューだけを使う。

### Q2. 隔離レビュアーの実行方法

- **A(推奨)**: ルーティンのセッションから `claude -p` / `codex exec` を隔離バンドルを作業ディレクトリにして起動する。物理的に遮断でき、追加の費用が無い。ルーティン環境で動くかは未確認。
- B: GitHub Actions で実行する。遮断は確実だが、API キーの管理と Actions の時間(private の無料枠)が要る。
- C: 同じセッションのサブエージェントに指示だけで守らせる。旧環境と同じで、遮断の保証は無い。

A が動かなかったときに B と C のどちらに倒すか。

### Q3. データリポジトリのパス

- **A(推奨)**: ASCII(`works/hoshiyomi/episodes/007/text.md`)。URL・API・シェルで扱いやすく、題名を変えてもパスが変わらない。
- B: 日本語(`作品/星詠みのセロ/第007話/本文.md`)。GitHub の画面で読みやすい。

### Q4. マージ(確定)の操作
